# Papertrend Product Context

## Product

Papertrend is a research-paper intelligence workspace. It helps researchers and
academic teams upload papers, monitor analysis, organize a repository, inspect
corpus-level patterns, and ask grounded questions whose evidence remains tied to
the source papers.

## Primary Users

- University researchers, lecturers, and graduate students.
- Small research groups evaluating a shared paper corpus.
- Beta users who need clear progress and recoverable workflows more than dense
  configuration.

## Core Jobs

1. Upload a paper and understand exactly what is happening during analysis.
2. Organize papers into projects and folders without losing project isolation.
3. Scan the repository, dashboard, and processing history efficiently.
4. Ask questions across selected papers or a repository and inspect citations.
5. Recover from failed, delayed, empty, or partially analyzed states safely.

## Product Principles

- Evidence before spectacle: claims and charts must trace to source material.
- Progress must be visible: long-running work always names its current stage.
- Repository context must remain obvious across navigation and AI workflows.
- Product surfaces favor scanability and repeated action; public surfaces can be
  more editorial.
- Security and owner/project isolation are part of the interface contract.

## Voice

Calm, precise, direct, and academically literate. Avoid hype and avoid describing
the interface instead of helping the user complete the current task.

## Constraints

- Preserve the existing Papertrend identity and blue/cyan signal colors.
- Support light and dark themes, keyboard navigation, and mobile use down to
  320px.
- Use local font stacks so Cloud Build does not depend on external font hosts.
- Keep production behavior and existing route ownership intact during redesigns.
